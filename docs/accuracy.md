# 判定精度の記録

ルールや特徴量を変えるたびに、ここに数字を足す。古い行は消さない。

## 測り方（フェーズ2で本格化）

1. 社長が自宅・散歩中に録った吠え声 20件以上。各ファイルに「本当の気持ち」を1つ付ける（警戒／威嚇／要求／遊ぼう／さみしい／うれしい）。
2. ファイルは `tests/real/`（**リポジトリには入れない**。`.gitignore` 済みにする）。
3. 学習なし（ルールのみ）と、半分を教えたあと（kNN あり）の2通りで的中率を出す。
4. 6択のあてずっぽうは 17%。犬の鳴き声の文脈当ては研究でも人間で 40% 前後（Molnár 2006 の6文脈課題）なので、**40% を超えたら上出来、30% 台なら普通**。

## 本物の犬 40 本から分かったこと（2026-11-03、ESC-50）

- **合成 fixtures は本物より規則的すぎた**。本物の連吠え（3 回以上、32 本）の間隔のばらつき gapCv は中央値 0.58（25–75%: 0.43–0.71）。合成 4 連吠えは 0.0 に近い。ルールの「規則的 → 要求」は本物ではほぼ効かず、**要求が 40 本中 3 本しか出ない**。gapCv のしきい値（いま `1 - clamp(gapCv,0,1)`）は本物の分布に合わせて見直す候補（正解ラベルが付いてから）。
- ピッチは 40 本すべてで取れた（f0=0 なし）。ただし 1000Hz 超（1036 / 1071 / 1123Hz）が 3 本、152Hz が 1 本あり、小型犬か、オクターブ違いの誤推定か、本物の音で要確認。
- 犬以外の音は、音量だけの検出だと 93% を「吠え」として拾う。特に咳・笑い・ノックは短く大きいので犬と区別がつかない。これが YAMNet 前段（plan #14）の必要性の数字。
- ルールの出力は最大でも 35% 前後で、1 位と 2 位の差は小さい（UI の「自信」が「低め」になるのが普通）。
- **YAMNet は本物の犬 40 本を 40 本とも「犬」、犬以外 40 本を 0 本「犬」と判定**（しきい値 0.3）。合成音では 1〜8% だったのは合成音のせいで、本物なら中央値 98%。前段に入れる価値は数字で確認できた（plan #14 へ進める）。ESC-50 の犬は「はっきり吠えている」クリップが中心。CC0 5 本で確かめると、うなりは 98% で問題なし、**くんくん（38%）と息（49%）はしきい値 0.3 の近く**。「さみしい」のクーン声を落とさないためには 0.3 より上げない方がよい。遠吠えはまだ本物で確認できていない。

## 吠えの塊で測って分かったこと（2026-11-04）

- **本体に入れるときの単位＝塊で測ると、犬の拾い率は 100% → 92%、犬以外の誤判定は 0% のまま**。しきい値 0.3（最大）は塊でも妥当。0.2 に下げても犬 93%・犬以外 0% で、ほぼ変わらない。
- **落ちるのは「吠えていない犬」**: くんくん（whimper）はファイル全体で 38% だったのが塊では 1〜2%（上位は Speech）、息（panting）は 49% → 11%／0%。短い塊（約 1 秒、ゼロ埋め）だと YAMNet はこれらを犬と認識しない。はっきり吠えている ESC-50 の 40 本でも 1 本（1-100032、62% → 10%）が塊では落ちる。
- 「犬系クラスの合計」で救う案は効かなかった（塊でも全部落ちる本は 3 本のまま）。
- **plan #14 の設計への影響**: (1) しきい値 0.3・最大のまま。(2) 塊だけを渡すのではなく、リングバッファから前後を広げて **最低 2〜3 秒の実音** を渡す案を次に測る（ゼロ埋めより文脈がある方が 1-100032 のようなケースを救えるはず）。(3) それでもくんくん・息は落ちるので、**「犬以外」と判定した塊は捨てるのではなく「判定はするが育成ログには残さない／薄く表示」** のように、「さみしい」のクーン声を失わない設計にする。(4) 処理時間は塊 1 つあたり CPU で約 0.3〜0.5 秒（Actions のランナー）。

## 塊を前後に広げて分かったこと（2026-11-05）

- **前の実音を足して最低 2 秒にすると、犬の塊の拾い率が 92% → 94% に上がり、犬以外の誤判定は 0% のまま**。塊そのままでは落ちていた ESC-50 1-100032（10% → 86%）と 3-136288 の 2 塊目（26% → 67%）が救われ、逆に落ちた塊も、新たに誤判定した犬以外の塊も 0。
- **3 秒まで広げるとかえって悪い面が出る**: 小型犬の塊 1 つ（1% → 44%）は救われるが、3-180256 の塊が落ち（34% → 28%）、赤ん坊の泣き声の塊が 0% → 32% で「犬」になる（犬以外 1/51）。文脈を長くしすぎると周りの音を拾う。
- **くんくん（1/1/2%）と息（21%／6%）は 2 秒でも 3 秒でも落ちる**。YAMNet の上位は Speech（くんくん）、Animal / Rodents（息）。範囲を広げても救えないので、plan #14 の設計 (c)「犬以外っぽい塊は捨てずに、判定はするが育成ログには自動では残さない」で受ける。
- しきい値は 2 秒のとき 0.2〜0.4 で 92〜95%、犬以外 0% で変わらず。**0.3 のまま**。
- 本体での実装: `Listener` が塊を確定したとき、リングバッファから前を足して 2 秒ぶんを YAMNet 用に出す（未来の音は待たない）。`clustersFromEvents(events, total, { minSec: 2 })` と同じ範囲。

## 「なぜ」の言葉を本物の犬の分布に照らして（2026-11-11、机上）

判定の「なぜ」（`classify.explain()`、2026-11-09）は、ルールの項が 0.6 以上のものを挙げる。本物の犬 40 本の分布（2026-11-03: f0 541Hz、1 回 145ms、間隔 509ms、cent 1571Hz、gapCv 0.58、それぞれ 25–75% の幅）に合わせた乱数 2 万件で、どの言葉がどれくらい出るかを数えた（正解ラベルは無いので的中率ではない。ルールの数字は触っていない）。

- 言葉の境目（Hz / ms に直したもの）: 声が高い f0 ≥ 590Hz／声が低い ≤ 320Hz／声が高すぎない ≤ 510Hz／間隔が短い ≤ 300ms／間隔がゆったり ≥ 880ms／間隔がそろっている gapCv ≤ 0.4／1 回が短い ≤ 590ms／1 回が長い ≥ 710ms／こもった cent ≤ 1300Hz／明るい ≥ 1600Hz／回数が多い n ≥ 5。
- 「なぜ」に出る割合: **1 回が短い声 89%**、回数が多い 43%、声が高い 37%、声が高すぎない 26%、間隔が短い 14%、間隔がゆったり 13%、間隔がそろっている 1%、声が低い 1%、こもった 1%、1 回が長い 0%、明るい 0%。項の数は 1 個 13%・2 個 48%・3 個 39%、「決め手なし」0%。
- ルールだけの 1 位: 遊ぼう 47%・警戒 42%・うれしい 10%・要求 1%・威嚇 1%・さみしい 0%。ESC-50 の実測（遊ぼう 16・警戒 14・うれしい 5・要求 3・威嚇 1・さみしい 1 ／ 40 本）とほぼ同じ形。
- 分かったこと: (1) **「1 回が短い声（145ms）」はほぼ毎回出る**。本物の吠えはたいてい 120〜220ms なので、嘘ではないが「犬の吠えとしては普通の長さ」を短いと言っている。言葉としては不自然ではないが、決め手として弱い。(2) **本物の間隔 300〜880ms は「短い」にも「ゆったり」にも入らない空白地帯**で、間隔の言葉は 4 回に 1 回しか出ない。(3) 「1 回が長い声」は本物の吠えには出ない（710ms 以上）ので、ルールだけでは さみしい・威嚇 がほとんど 1 位になれない。クーン声・うなりは吠えより長いはずだが、ESC-50 は吠え中心なので、本物のクーン声・うなりの長さは CC0 5 本か社長の録音で見る。(4) f0 が 1000Hz を超える本（40 本中 3 本。オクターブ違いの誤推定かもしれない）では「声が高い（1123Hz）」と数字がそのまま出る。
- 直すとしたら（#13b、正解ラベルが来てから）: 長さの境目を本物の分布の前後（たとえば 短い ≤ 120ms／長い ≥ 250ms）に、間隔の境目を 短い ≤ 350ms／ゆったり ≥ 650ms あたりに寄せる。**今夜は言葉も数字も変えていない**（判定の数字を動かすのは正解ラベルが来てから、と決めているため）。再現: 上の分布で乱数を作り `terms()` と `explain()` を通す（`docs/daily/2026-11-11.md`）。

## CC0 5 本の声 1 回ごとのピッチ・明るさ・音量（2026-11-13、`lab-yamnet` run 43280755707）

`tests/lab/features-check.mjs` に足した 2 枚目の表（`report.mjs` の `eventToneReport`）。11-12 の表で「1 回の長さでは さみしい・威嚇 を出せない」と分かったので、代わりに「さみしい＝ピッチの動き or 音量の小ささ」「威嚇＝ピッチの低さ」が数字で見えるかを確かめた。声 1 回ごとの f0（Hz、取れた声だけ）、明るさ cent（Hz）、音量 level（dBFS、検出器が見た RMS のピーク）の中央値と 25–75%。「低い」= 320Hz 以下（いまの「声が低い→威嚇」の境目）、「高い」= 590Hz 以上、「こもった」= 1300Hz 以下、「明るい」= 1600Hz 以上。音量は録音ごとに基準が違うので、同じファイルのいちばん大きい声から何 dB 下か（声の大小のばらつき）を見る。

- **威嚇＝ピッチの低さ は半分見える**: うなりは声 1 回ごとに見ると f0 358Hz（228–449）で、**半分が「低い ≤320Hz」に入る**（小型犬の吠え・くんくんは 0%）。ただし大型犬の吠えも 36% が低い側に入るので、「低い＝威嚇」だけだと大型犬のふつうの吠えが威嚇に寄る（11-12 のルール判定でも大型犬は 警戒 27%、うなりは 警戒 27% で並んでいた）。低さに「声の大小のばらつき」（下）を組み合わせる余地はある。
- **さみしい＝音量の小ささ は「ファイル内のばらつき」としてなら見える**: くんくんは 27 回のうち、いちばん大きい声から **中央値 5.4 dB 下（25–75%: 2.3–6.5）**。吠え（大型 1.6 dB、小型 0.7 dB）は毎回ほぼ同じ大きさで鳴くのに対し、くんくんは小さい声が混ざる。ただし遊びのうなりも 4.6 dB で同じくらいばらつくので、これだけでは くんくん と うなり は分かれない。録音ごとの音量の基準は -22〜-24 dBFS でそろっていた（配布元で正規化されているらしい）ので、絶対値では比べられない。
- **さみしい＝ピッチの動き は見えない**: くんくんの f0 の幅（25–75%）188Hz は、大型犬の吠え 256Hz・うなり 221Hz より狭い。声 1 回の中の上がり下がり（クーンの「上がって下がる」）は、いまの検出器が 1 回につき f0 の中央値 1 つしか出さないので測れていない。測るなら 1 回の中で f0 を 3〜6 点取って傾きを出す必要がある（`features.js` の `picks` はすでに最大 6 点見ているので、中央値のほかに「最初と最後の差」を出すのは小さい変更）。
- **いまの「さみしい」のルール（1 回が長い 0.5・声が高い 0.3・明るい 0.2）は、本物のくんくんに 3 つとも当たらない**: 長さ 85ms（長くない）、f0 459Hz（高い ≥590 は 26% だけ）、cent 1248Hz（**明るいどころか 63% が「こもった」**。小型犬の吠え 1887Hz より暗い）。11-11・11-12 の「ルールだけでは さみしい 0%」の理由がこれで 3 つとも数字で言える。直す方向（正解ラベルが来てから）: さみしい は「長い・高い・明るい」ではなく「**吠えより小さい声が混ざる（声の大小のばらつき）・中くらいの高さ（400〜600Hz）・こもり気味**」。威嚇は「低い」に「大小のばらつき」を足す。
- 息（パンティング）は 4 回だけで、音量のばらつき 12.8 dB・f0 281Hz と極端。YAMNet が塊では落とす（11-05）ので、本体ではもともと薄い表示になる声。
- 注意: 1 種類 1 本ずつ（1 頭ずつ）の数字なので、犬の個体差と見分けがつかない。正解ラベル付きの本物の犬（社長の録音）で確かめるまで、判定の数字は変えない。

## 既知の弱点（2026-11-01）

- 規則的すぎる連吠えは「要求」に寄る。本物の犬は間隔がばらつくので、実データで見直す。
- 人の声・テレビ・物音も「吠え」として拾う可能性がある（フェーズ2の YAMNet で除外予定）。
- 「威嚇」はピッチが低く長い声が前提。小型犬の威嚇は拾いにくいかもしれない。
